# 技术文档

## 先建立事实清单

阅读用户提供的模板、现有文档、源码和配置，明确读者、文档用途、版本与交付格式。为功能、命令、路径、架构关系和运行前提记录来源；历史资料与当前实现冲突时说明差异。

不虚构日期、人员、工时、验收结果、指标或生产架构。未知项留空或标记“待核实”；规划、已实现、已验证分别表述。命令应来自当前项目，不能为了让文档完整而补上并不存在的入口。

## 组织内容

- 操作手册：使用前提 → 操作步骤 → 预期结果 → 常见失败及处理。明确每条命令在哪台机器、哪个目录执行，需要什么权限。
- 部署或变更说明：适用版本 → 依赖与已有离线物料 → 配置 → 执行顺序 → 健康检查 → 回退与数据影响。不把联网下载命令当作内网已具备的物料。
- 故障报告或应急预案：现象/触发条件 → 角色与联系方式占位 → 证据/判断 → 处置步骤 → 恢复验证 → 记录。计划中的演练不写成已完成。
- 接口或架构说明：输入、输出、状态所有者、错误行为和调用方向；按已确认事实绘图，图与正文使用相同术语。

## 交付前核对

检查目录、版本、编号、交叉引用、命令与占位值；把“执行过的验证”和“读者后续需验证的步骤”分开写清。示例使用虚构标识，不带凭据、真实个人信息或内部地址。

复用已有模板与本地生成工具。未指定格式时使用 Markdown；要求 Office 文件时检查现有工具可用性，保留原文件并另存。无法导出或渲染时说明限制，不把源码结构检查当作版式验收。用户要求保留正文或格式时只改授权部分。
